# 图表生成

本阶段 Skill 由 `math-modeling-orchestrator` 调用。只执行 Stage 4，使用真实结果文件及执行证据。阶段路由、项目状态、版本、回退和 Gate 判定由 orchestrator 负责。

## 输入

- Stage 3 产生的结果文件及执行记录。
- 模型契约中的变量定义、单位和验证标准。
- orchestrator 提供的展示约束。

## 职责

1. 绘图前检查结果数据的标签、单位、范围、缺失值和聚合方式。
2. 仅在图表回答建模问题或支撑明确论断时选择相应图表/表格。
3. 使用清晰的标签、图例、刻度、标题、说明、误差/敏感性信息和一致单位。
4. 保留每个视觉元素和统计量的源数据及命令追踪关系。
5. 检查可视化结论没有超出真实执行结果的支持范围。

## 输出

在 `results/` 或 `figures/` 下创建所需图表/表格，并创建 `results/evidence-map.md`。证据映射必须将每条结果论断、图或表关联到源结果文件、执行记录、相关模型契约条目和变换过程；适用时还要关联可能引用它的论文章节。记录生成命令，并说明排除或变换的数据。

## 边界与禁止行为

- 只能使用真实代码执行产生的结果；不得虚构、手调或凭视觉推断数值。
- 不修改源结果、模型定义或求解行为来改善外观。
- 不撰写论文、审查报告或超出简短图表说明的结论。
- 不编辑 `project-state.json`，不重新定义版本或回退机制，不声明任何 G1-G6 结果，不推进到 Stage 5。
- 不为填满交付清单而生成无标签或不可追溯的图表。

向 orchestrator 返回图表、表格和证据映射路径、生成命令及追踪缺口。由 orchestrator 执行 Gate 检查。
