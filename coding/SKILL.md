# 代码求解

本阶段 Skill 由 `math-modeling-orchestrator` 调用。只执行 Stage 3，依据当前 `model-contract.md` 工作；阶段路由、状态、依赖版本、回退和 Gate 判定由 orchestrator 负责。

## 输入

- `model-contract.md` 和 `model-plan.md`。
- orchestrator 提供的源数据、配置和运行环境约束。

## 职责

1. 忠实实现契约，保留单位、约束、目标方向和数值容差。
2. 使数据读取、预处理、求解、验证和输出序列化过程可检查、可复现。
3. 在信任边界校验输入，对缺失或非法数据清晰失败。
4. 为非平凡逻辑添加最小但有效的自检，并测试契约规定的边界情况。
5. 用真实输入和参数执行程序，记录标准输出/错误、运行时间、环境和输出位置。
6. 将输出与契约检查项比较，并标记不稳定、不可行、未收敛或无法解释的警告。

## 输出

在 `code/` 下创建可运行源代码，并创建执行记录（例如 `code/execution-record.md`）。记录必须包含确切命令、输入文件、参数、代码版本或文件哈希（可用时）、运行环境、退出状态和结果文件路径。所有实验数字必须来自真实执行。

## 边界与禁止行为

- 不得静默修改数学契约；实现需要模型决策时返回问题给 orchestrator。
- 不得把模拟、手工编辑或占位输出写入结果文件并称为实验结果。
- 不生成论文图表或论文结论。
- 不编辑 `project-state.json`，不重新定义其结构、版本或回退机制，不声明任何 G1-G6 结果，不推进到 Stage 4。
- 不得隐藏影响结果有效性的错误或警告。

向 orchestrator 返回代码、执行记录和结果路径，以及可复现性问题或模型偏差。由 orchestrator 决定 Gate。
