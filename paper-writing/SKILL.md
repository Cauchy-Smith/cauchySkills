# 论文写作

本阶段 Skill 由 `math-modeling-orchestrator` 调用。只执行 Stage 5，使用当前模型契约、执行结果、图表、表格和证据映射。阶段路由、状态、版本、回退和 Gate 判定由 orchestrator 负责。

## 输入

- `problem-analysis.md`、`model-plan.md` 和 `model-contract.md`。
- 当前执行记录、结果文件、图表/表格以及 `results/evidence-map.md`。
- orchestrator 提供的格式、引用和篇幅要求。

## 职责

1. 组织完整论文：问题、假设、符号、模型、求解方法、验证、结果、敏感性/局限、结论和参考文献等。
2. 按 `model-contract.md` 一致地解释公式和算法，保留定义和单位。
3. 插入带有题注、编号、来源/证据引用和交叉引用的图表。
4. 将每个论文数字、比较和事实论断追溯到证据，区分计算结果、来源事实、假设和解释。
5. 说明局限、失败检查、不确定性和复现信息，不夸大结论。
6. 检查符号、单位、小数、百分比、图表引用和结论的内部一致性。
7. 使用项目允许的 LaTeX 编译工具编译主 `.tex` 文件，检查编译错误、引用/交叉引用和生成的 PDF 是否可读。

## 输出

在 `paper/` 下创建 LaTeX 论文源文件（主 `.tex` 文件及必要的本地资源），并将其成功编译为最终 PDF。保留可复现的编译命令和日志（例如 `paper/compile-record.md`）。结果章节必须具备证据链，并包含足够的执行/来源信息供审查。未解决的证据缺口必须明确标记。PDF 是本阶段面向用户的最终论文产物，`.tex` 源文件和编译记录用于追溯与复现。

## 边界与禁止行为

- 不虚构数字、引用、实验、数据来源或论断；每个数字都必须追溯到结果证据。
- 不静默修复模型、重跑代码、修改结果文件或重绘图表；发现差异时返回给 orchestrator。
- 不把未成功编译的 `.tex` 文件或未验证的 PDF 作为最终论文交付。
- 不撰写合规报告，不声明任何 G1-G6 结果。
- 不编辑 `project-state.json`，不重新定义其结构、版本或回退机制，不推进到 Stage 6。
- 不使用已标记为过期的模型、结果或图表。

向 orchestrator 返回草稿路径，以及证据缺口、不一致项和待审假设。由 orchestrator 决定 Gate。
