# 真实「解题思路」文件索引

**何时读**：不是必经步骤。只在两种情况下翻——① §5 题型判定拿不准，想看看别人对同类小问贴了什么标签；② §3 隐含目标或 §7 结构性发现疑似漏项，想对照别人的审题视角。

**在哪**：这些文件在**本 skill 所在的项目根**的 `write/` 下——即从本 skill 目录逐级向上，找到同时含 `resource/`、`code/`、`write/` 的那一层，不是当前赛题工作目录。下面的路径都相对该目录。

若本 skill 被装到项目之外（如全局 skills 目录），这层关系就不存在了，`write/` 也就找不到——此时按上面那句话自行定位，或直接跳过本文件（它只是可选的对照材料）。`write/` 有 1.8 GB，**换项目时不必随行**；定位规则的完整说明见 `math-modeler/SKILL.md` 的「项目资产位置」。

**用途只有一个：看别人怎么审题**——小问怎么拆、条件怎么归位、题型怎么判、坑在哪。**不要抄结论**：这些是往届不同题目的思路，题目不同则结论无效。

## 四、怎么用（只看结构，不抄内容）

读一篇思路文件时，只提取这四样：

1. **它把小问拆成了什么** —— 对照自己的 §3，看有没有漏掉隐含目标。
2. **它把哪些句子当成了约束** —— 对照自己的 §2.4，看有没有把背景误当约束、或漏掉真约束。
3. **它给每问贴了什么题型标签** —— 对照自己的 §5，题型不一致时回看信号词。
4. **它点出了哪些坑** —— 单位口径、数据缺口、结论依赖。对照自己的 §7 结构性发现与 §8 歧义表。

**读法提示**：这些文件页数很大（最多 148 页），按页翻目录与章标题即可，不要整篇加载。若用文本工具读，先看前几页有没有内容——没有就直接换成看图。

## 五、与其它两个库的分工

- `write/` —— 审题与写作参考（本 skill 与 `math-writer` 用）。
- `code/` —— 45 个组合模型案例源码，`math-coder` 的素材库。
- `resource/` —— 基础模型实现，`math-modeler` 的选型目录。

审题阶段**不碰** `code/` 与 `resource/`——那是选定题型之后的事。
