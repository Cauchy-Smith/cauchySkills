# 审题分析框架

剖析简报的每一节由本文件的规则产生。判定有歧义时按这里的标准裁，不要凭感觉。

## 一、四类信息的判定标准

| 类别 | 判定标准 | 例 |
| --- | --- | --- |
| 背景信息 | 换成别的场景，模型不变 | 「随着新能源汽车产业快速发展……」 |
| 核心问题 | 读出来是一个「要你回答的疑问」 | 「预测 2025—2029 年保有量」 |
| 已知条件 | 提供了数值、关系或附件，可被模型直接使用 | 「2019—2024 年保有量为 12.3、18.6……万辆」 |
| 约束条件 | 限制解空间的边界，违反即不可行 | 「总预算不超过 5000 万元」「响应时间 ≤ 2 秒」 |

**边界情况**：

- 一句话同时含问题与条件时，**按语义拆成两行**，分别归位，并都引用同一句原文。
- 「要求 / 需 / 应」引导的多半是核心问题或约束：含「求」的进核心问题，含「不超过 / 不超过 / 至少 / 必须」的进约束条件。
- 「例如 / 如 / 可参考」引导的内容是**说明**，不是条件——不要当成硬性数据。
- 无法归入四类的整句，标为「无关叙述」并保留，不要删——将来可能用于问题重述。

**表格格式**：

```
| 序号 | 原文（节选） | 内容 | 出处 |
| --- | --- | --- | --- |
| B1 | 「随着……快速发展」 | 背景：产业处于扩张期 | 题目第 1 段 |
```

`出处` 写「题目第 N 段」或「附件K」。**没有出处的行不允许存在。**

## 二、隐含目标识别套路

题目常常只说一半。逐问套下面的模式，命中的写进「隐含目标」，未命中的写「无」并给理由。

| 表面要求 | 通常还要 | 为什么 |
| --- | --- | --- |
| 给出最优方案 | 验证可行性 + 约束松紧分析 | 最优解若不可行等于没做 |
| 给出排序 / 排名 | 说明权重来源与排序稳定性 | 权重不同排名会翻转 |
| 给出预测值 | 给出区间与精度等级 | 点预测无法支撑决策 |
| 建立模型 | 说明假设的适用边界 | 假设不成立时结论失效 |
| 给出分类结果 | 说明类别数怎么定、结果稳不稳 | 类别数是人为选择 |
| 分析影响因素 | 给出显著性 / 关联强度 | 相关不等于重要 |
| 求解 / 计算 | 说明算法为什么能收敛 | 不收敛的解没有意义 |
| 「并对结果进行分析」 | 基础解读 + 深层归因 | 这是独立得分点 |
| 「说明理由 / 论证」 | 必须有可核验的依据 | 空泛的「因为更合理」不得分 |

## 三、六类题型信号词表

逐问统计信号词出现情况，取最强者为主题型；出现两类强信号即为**组合题型**，写明谁先谁后。

| 题型 | 信号词 | 细分判据 |
| --- | --- | --- |
| 优化类 | 最大 / 最小 / 最优 / 成本最低 / 收益最高 / 分配 / 调度 / 选址 / 路径 / 方案 | 出现「同时满足 / 权衡 / 兼顾」→ 多目标；否则单目标 |
| 预测类 | 预测 / 未来 N 年 / 趋势 / 估计 / 演化到 | 有等间隔时间序列 → 时序；有自变量集合 → 回归 |
| 评价类 | 综合评价 / 排序 / 优劣 / 指标体系 / 权重 / 打分 | 指标需自行构建 → 体系设计 + 赋权两步 |
| 机理分析类 | 传播规律 / 演化 / 动力学 / 守恒 / 生长 / 衰减 / 反应 | 要求「解释机理」而非「拟合数据」 |
| 分类聚类类 | 分组 / 分类 / 聚类 / 划分 / 识别 / 分层 | 有标签 → 分类；无标签 → 聚类 |
| 统计检验类 | 是否显著 / 相关性 / 影响 / 差异 / 检验 | 要给出 p 值或置信区间，而非仅描述性统计 |

**判断依据必须引用题目原句**，写成「题型：优化类（多目标）；依据：题面『在成本不超过 X 的同时使收益最大』」。

**组合题型**：一问里出现两类强信号时写成「组合：A + B」，并写明先后（如「评价类 + 优化类：先赋权评价，再做预算敏感性优化」）。

### 六类之外的附加要求

有一类要求不属于「算什么」，而属于「怎么说明」，硬塞进六类会丢。逐问单列在 §5 的「附加要求」列：

| 附加要求 | 信号词 | 记法 |
| --- | --- | --- |
| 论述 | 说明理由 / 适用条件 / 局限 / 讨论 | 「论述：说明模型适用条件与局限」 |
| 敏感性 | 参数变化 / 放宽 X% / 扰动 / 若……会怎样 | 「敏感性：预算放宽 20%」 |
| 稳健性 | 抗干扰 / 数据波动 / 误差影响 | 「稳健性：输入加噪」 |
| 推广 | 推广 / 可迁移 / 同类问题 | 「推广：可扩展至同类场景」 |
| 数据补充 | 若数据不足 / 自行查找 / 补充数据 | 「补充：外部数据获取途径」 |

同一问可以同时有多个附加要求，也可以一项都没有。**这些是独立得分点**，漏记就会在论文里整段缺席。

## 四、依赖关系的四种类型

| 类型 | 形式 | 写法 |
| --- | --- | --- |
| 前置依赖 | 问 2 的输入是问 1 的输出 | `问1 →问2（传递：最优选址集合）` |
| 参数依赖 | 参数 A 决定 B 的计算口径 | `参数A ⇒参数B（传递：A 的取值）` |
| 数据依赖 | 某附件只服务某一问 | `附件3 →问4（传递：距离矩阵）` |
| 结论依赖 | 后一问要用前一问的结论做前提 | `问3 结论 →问4 假设` |

没有入边和出边的小问显式标为「独立」，不要留白——留白会让人以为漏了。

```
问1 ──(最优选址集合)──▶ 问2 ──(预测需求)──▶ 问3
附件1 ─────────────────────────▶ 问1
问4：独立
```

## 五、数据门槛初判

只做**题型级粗筛**，判断「这个数据量支不支持做这类题」，逐模型的数据门槛在建模手的 `math-modeler/references/model-catalog.md`，这里不重复。

| 题型 | 粗筛 | 不够时的常见出路 |
| --- | --- | --- |
| 时序预测 | 有等间隔序列，长度 ≥ 2 个周期 | 小样本改灰色/机理模型 |
| 回归预测 | 样本数 ≥ 自变量数的 10 倍 | 降维或改小样本方法 |
| 评价 | 方案数 ≥ 3，指标数适中 | 指标过多先降维 |
| 优化 | 决策变量规模与约束可枚举或可求解 | 加启发式算法 |
| 分类 | 每类有足够有标签样本 | 改无监督或半监督 |
| 聚类 | 样本量足以形成簇 | 降维后再聚类 |
| 统计检验 | 每组样本量满足检验前提 | 改非参数方法 |

输出写成「够 / 不够 / 需补充」，并写明缺口是**样本量**、**字段**还是**时间跨度**。

组合题型按**各组成部分分别套**：如「评价类 + 优化类」的小问，先按评价类看方案数与指标数够不够，再按优化类看决策变量规模。

## 六、常见审题陷阱

- **把背景当约束**：「行业竞争激烈」不是约束，「预算不超过 5000 万元」才是。
- **漏掉论述型要求**：题目里「并说明理由」「讨论适用性」「分析灵敏度」都是独立得分点，常被当成客套话跳过。
- **量纲不统一**：万元 / 元、万辆 / 辆、分钟 / 小时、km / m——在剖析阶段就要把每个附件的单位写成统一口径，标出需要换算的位置。
- **把示例当真值**：题目里的「例如」「如」是说明性示例，不是数据。
- **忽略附件的表头与说明行**：附件前几行常是口径说明（如「单位：万元」「数据为年末口径」），漏读会导致整题口径错误。
- **小问有先后却并行处理**：问 2 依赖问 1 时，问 2 的假设必须与问 1 的结论一致。
- **只盯数字、漏掉口径**：「保有量」是当年新增还是累计？「效率」是比率还是绝对量？口径不明要进歧义表。
