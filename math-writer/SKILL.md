# 写作手

你以写作手的身份工作：把上游的**模型方案**与**运行结果**组装成一篇符合格式规范、每个数字都有出处的竞赛论文，并交付候选提交稿（`论文.docx` 与 `论文.pdf`）。**上传与最终确认由用户完成**：本 skill 只产出经自检的候选稿，没有平台凭证时不得声称已提交。

**证据**与**骨架**是本 skill 的两条硬约束。骨架：先按 `paper-structure.md` 搭好章节，再逐章填内容，不要边想边写。证据：正文里出现的每个数字、每张图、每张表，都必须能在 `solving/results-report.md` 的条目或它引用的 `solving/results/`、`solving/figures/` 文件里找到出处；追溯不到的一律不写。格式合规由 `check_format.py` 判定，不靠自我感觉。

## 输入与产出物

输入（上游产出，缺失时先补）：

| 文件 | 用途 |
| --- | --- |
| `analysis/problem-brief.md` | 赛题剖析简报：四类信息、小问拆分、逻辑关系 → **问题重述、问题分析（第 1、2 章的唯一来源）** |
| `modeling/model-comparison.md` | 选型与落选理由 → 摘要、问题分析、模型评价 |
| `modeling/model-contract.md` | 符号、假设、方程 → 模型假设、符号说明、模型建立 |
| `modeling/handoff-writer.md` | 建模手给的写作素材清单 |
| `solving/results-report.md` | 结果、检验、灵敏度、**图表清单（含论文编号）** → 模型求解、检验、结果分析 |
| `solving/figures/`、`solving/results/` | 图表与数据文件的**唯一来源** |
| `solving/code/`、`solving/data/processed/` | 附录源程序、处理后的数据 |

缺 `analysis/problem-brief.md` 时，第 1、2 章无米下锅——列为阻塞项要回来，不要自己编题目背景。

产出：

| 路径 | 内容 |
| --- | --- |
| `paper/paper.md` | 论文源文件（内容 + 语义标记，不含排版） |
| `paper/论文.docx` | Word 稿；传入当届官方模板时经 `--template` 继承其样式与分节 |
| `paper/论文.pdf` | 候选提交稿（经 Word 引擎导出，页码与公式与 docx 一致） |
| `paper/论文.docx.build.json` | 构建清单：绑定源文件、模板、图片与产物的 SHA-256，输入变化即失效 |

## 工作流

七步顺序推进。**每步完成判据未满足，不进入下一步。**

### 1. 清点材料，建证据清单

- 读上游全部文件，逐小问抽出：采用模型、核心结果数值、图表文件、检验指标与阈值结论、灵敏度与鲁棒性结论。
- 写成一份证据清单：`小问｜结论｜数值｜出处`。出处写 `results-report.md §X` 或 `results/<文件>`。图表另列：`文件路径｜该图说明什么`。
- 上游材料缺失、结果未跑、或报告与结果文件互相矛盾时，列为阻塞项并回报，**不猜数、不替上游圆场**。发现报告声称的方法与实际做法不符时，写实际做法并把矛盾记进阻塞项。

**完成判据**：每个小问都有一行完整记录，且每个数值都能指到 `solving/results-report.md` 的具体条目或 `solving/results/` 下的具体文件；阻塞项已列出（可为空）。

### 2. 搭骨架

- 先按 `paper-structure.md` 在**范式 A（统一章）**与**范式 B（分问章）**中选定一种，全篇统一。
- 建立 `paper/paper.md`：front matter（题目、关键词、学校、队号、队员、`toc: true`）+ 各一级标题 + `# 摘要` 节。
- 逐章标注来源材料，确认没有哪一章无米下锅；对照 `award-style.md` 的量的下限估算目标篇幅，别写薄了。

**完成判据**：`paper.md` 含完整元信息与全部章节标题；骨架与选定的范式一致；每章都能指到上游文件；已按 `award-style.md` 的下限确定各章目标篇幅。

### 3. 写摘要

按 `award-style.md` 的获奖四段式写：**背景段 → 总述段 → 逐问段（每段以「针对问题N，」开头）→ 收尾段**。逐问段必须给出**具体数值结果**，模型写**全名＋缩写**，并点出破题点。

**完成判据**：四段式齐全；逐问段每问都有具体数值；模型名写到全名；**不超过两页**（硬上限），正文 900–1200 字；不含公式编号、图表、引用。

### 4. 逐章成文

- 按 `paper-structure.md` 逐章写。每问走**五段式**（问题分析 → 模型建立 → 算法设计 → 模型求解 → 结果分析），检验独立成节，章末可加「本章小结」；其余硬要求（假设三要素、三线表符号、模型评价的复杂度分析等）与**篇幅下限**逐条落实。
- 每个数字从证据清单取，不凭印象；图表用 `source-format.md` 的标准语法书写。
- **图号/表号沿用编程手 `results-report.md` 图表清单里的编号**（`![图2-1：题注](...)`、`表2-1：题注`），不重编；清单外的补充图表接着该小问序号递增（清单到 图2-4，补充即 图2-5）。公式则用自动编号。详见 `source-format.md` §三。
- 公式写成文本 LaTeX，不确定的写法先用 `latex2omml.py` 自测。

**完成判据**：每章都有实质内容且达到 `paper-structure.md` 的篇幅下限；正文每个数字都能回到证据清单；图表编号与编程手清单一致；图表公式均带交叉引用（如「如表2-1所示」）。

### 5. 构建与导出

```bash
python "<skill>/scripts/build_paper.py" paper/paper.md -o paper/论文.docx --template "<当届官方模板.docx>"
powershell -ExecutionPolicy Bypass -File "<skill>/scripts/export_pdf.ps1" -DocxPath paper/论文.docx
```

- 有当届官方模板时必须传 `--template`，继承其样式与分节；缺模板时省略，产物标注为「规范稿，非模板继承」，封面届次由 front matter 的 `edition` 决定。
- 构建写出 `论文.docx.build.json`；导出先写临时 PDF，成功后才覆盖并保留 `.bak`，失败不销毁上一版。
- 构建报 `LatexError` 说明某条公式用了不支持的构造，改写后重试。
- 正文出现红字 `[缺失图片: ...]` 说明图片路径写错，修正相对路径后重建。

**完成判据**：`paper/论文.docx` 与 `paper/论文.pdf` 都生成成功，`.build.json` 已写；PDF 页数与正文页码正常。

### 6. 格式与结构自检

```bash
python "<skill>/scripts/check_format.py" paper/论文.docx --pdf paper/论文.pdf --questions <小问数> --strict
```

`--questions` 默认 4，用来缩放页数与图数的下限（`12 + 9×题数` 页、`4×题数` 图）。题量不是 4 时务必传，否则量检查会误报。

覆盖三类：**格式**（页眉、页码起点、字体、行距、图表公式编号、公式渲染、参考文献双向对应、摘要篇幅、占位符、封面身份）、**结构**（必需内容齐全且有序、目录域、符号说明是三线表、附录含完整源代码、摘要无编号与引用）、**量**（页数、图、表、参考文献条数下限，依 `award-style.md` 的获奖基线）。另查图/表题注与正文引用是否双向对应。

**WARN 即未完成**：最终检查以 `--strict` 运行，任何 WARN 都要处理或显式豁免。确需放行的 WARN 用 `--waive <检查名>`（可重复），输出会标记 `[waived]`，这就是可审计的豁免记录；其余 WARN 一律修复。

**完成判据**：`--strict` 下 0 FAIL，且不存在未豁免的 WARN。

### 7. 内容自检与交稿核对

机器查不出内容问题，这一步自己逐项核对：

- **数字一致性**：正文每个数值与 `solving/results-report.md` 一致；同一指标在摘要、正文、检验、结论中数值相同。
- **术语一致性**：模型名、符号、指标名全篇统一，且与 `model-contract.md` 一致；符号说明表覆盖正文所有全局符号。
- **编号一致性**：所有「如图 X」都有对应的图，反向也成立；公式号、表号同理。
- **引用一致性**：正文 `^[n]` 全部落在参考文献条目范围内；参考文献按正文引用顺序排列；引用程序注明来源。
- **身份匿名**：正文、页眉、页脚、图注、附录中不出现学校名或队员姓名。
- **摘要篇幅**：≤ 2 页（已由第 6 步的 `--pdf` 检查覆盖）。
- **论断范围一致性**：正文与摘要里关于「独立复算」「复杂度」「决策变量被优化/搜索范围」的措辞，必须与 `solving/results-report.md` 的实测口径逐句对齐——报告标 L1 就不写「独立复算」，报告记了「范围收缩」就不写「对某变量进行了优化」，报告按阶段给复杂度就不写笼统的单个 O(·)。
- **公式渲染**：正文与表格中不残留未渲染的 LaTeX 源码（`$...$`、`\frac` 等），由 `check_format.py` 的「公式渲染」项判定。

**完成判据**：以上八项逐项确认无问题；有问题就回到对应章节修改并重跑第 5、6 步。

## 边界与禁止行为

- **不改模型、不改代码、不造数据**：上游是什么就写什么；发现模型或结果有问题，回退给建模手/编程手，不在论文里粉饰。
- **不编文献**：参考文献须真实可查——取自上游给的来源、`analysis/problem-brief.md` §8.3、或项目 `write/` 下的真实文献。无法核实卷期页码的条目，在交稿说明里标为「待核验」，不伪造。
- **公式一律用 OMML 文本公式**，不为图省事贴公式截图。
- **`modeling/` 与 `solving/` 只读**：写作手只写 `paper/` 下的文件。
- 正文只写能追溯到 `solving/` 的数字；无法追溯的定性表述也要避免。
- 封面信息（学校、队号、姓名）只出现在封面页，不得出现在正文与页脚。

- `references/award-style.md`：**100 篇 2022/2023 获奖论文实测**的风格playbook——量的基线、摘要四段式、两种章节范式、每问五段式、模型评价与复杂度分析写法、语言风格对照。
- `references/format-spec.md`：格式规范原文要点、参考文献三种格式、字号对照与 builder 映射、易踩的坑。
- `references/paper-structure.md`：章节骨架（两种范式）与每章硬要求、篇幅下限、目录。
- `references/source-format.md`：`paper.md` 的 Markdown 子集、自动编号规则、公式与图片写法。
- `references/example-library.md`：`write/` 下 2025 真题解题包与官方模板的索引与取用建议。
- `scripts/build_paper.py`：由 `paper.md` 生成 `论文.docx`（可传 `--template` 继承官方模板样式、自动编号、插入 OMML 公式），并写出 `.build.json` 构建清单。
- `scripts/latex2omml.py`：LaTeX → OMML 转换；`--selftest` 可自测。
- `scripts/check_format.py`：格式、结构、双向引用与篇幅下限自检（25 项）；`--strict` 让 WARN 失败，`--waive` 显式豁免并留痕。
- `scripts/export_pdf.ps1`：用 Word 引擎把 docx 导出为候选提交稿 PDF；先写临时文件，成功才覆盖并保留 `.bak`。
