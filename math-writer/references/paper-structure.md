# 论文结构与各章要求

华为杯论文的标准骨架。编号与标题写进 `paper/paper.md` 的一级标题即可，builder 会自动编号。

量的基线与摘要写法见 `award-style.md`（100 篇 2022/2023 获奖论文实测）。本文件管**结构与每章要写什么**。

## 选一种章节骨架

获奖论文有两种主流组织方式，**选一种，全篇统一**：

**范式 A·统一章**（各问共用一套模型时）：`问题重述 / 模型假设与符号说明 / 基本模型 / 问题一、二的分析与求解 / 问题三的分析与求解 / … / 模型评价 / 参考文献 / 附录`

**范式 B·分问章**（各问模型差异大时）：`问题重述 / 问题分析 / 模型假设 / 符号说明 / 问题一：模型建立与求解 / 问题二：模型建立与求解 / … / 模型分析与评价 / 参考文献 / 附录`

两种范式共同的必需内容与来源：

| 内容 | 来源材料 |
| --- | --- |
| 摘要页（题目 / 摘要 / 关键词） | `modeling/model-comparison.md`、`solving/results-report.md` |
| 问题重述 | `analysis/problem-brief.md` §2 四类信息、§3 小问拆分 |
| 问题分析 | `analysis/problem-brief.md` §3 目标、§4 逻辑关系、§5 题型；`modeling/model-comparison.md` |
| 模型假设 | `modeling/model-contract.md` |
| 符号说明 | `modeling/model-contract.md` 符号表 |
| 模型建立与求解（逐问） | `modeling/model-contract.md`、`solving/results-report.md` |
| 模型检验 | `solving/results-report.md` 检验与灵敏度 |
| 模型的评价与推广 | `modeling/model-comparison.md`、`solving/results-report.md` |
| 参考文献 | 正文引用顺序 |
| 附录 | `solving/code/`、`solving/data/processed/`、`solving/results/` |

「模型假设」「符号说明」可以合并成一个一级章（如 `2 模型假设与符号说明`）；「模型检验」可以作为每问章内的小节（如 `5.5 模型检验`），不必单列一级章。**这些内容必须出现，但层级可以按范式调整**——`check_format.py` 按内容而不按层级判定。

## 篇幅与图表密度（量的下限）

依据 100 篇获奖论文实测（中位：全文 61 页、正文 45 页、图 21 张、表 5 张、参考文献 9 条）。**写得薄是硬伤**，篇幅直接反映工作量。

页数与图数随**题量**缩放：`页数下限 = 12 + 9 × 小问数`，`图数下限 = 4 × 小问数`。下表按 4 问列出。

| 部分 | 下限（4 问） | 获奖中位 | 说明 |
| --- | --- | --- | --- |
| 摘要 | ≤2 页（硬上限） | 999 字 | 推荐 900–1200 字 |
| 全文（不含封面） | ≥48 页 | 61 页 | `check_format.py --questions 4` 判定 |
| 正文（不含参考文献与附录） | ≥30 页 | 45 页 | |
| 模型建立与求解 | ≥ 正文的 50% | — | 主体，不能只占几页 |
| 每问的模型建立与求解 | ≥4 页 | — | 含推导、算法、求解、结果、检验 |
| 全文图 | ≥16 张 | 21 张 | |
| 每问图 | ≥4 张 | — | 覆盖不同侧面，不是同一结果换配色 |
| 全文表 | ≥4 张 | 5 张 | |
| 模型检验 | ≥1.5 页 | — | 检验方法 + 步骤 + 结果 + 灵敏度 |
| 参考文献 | ≥10 条 | 9 条 | 中外结合，正文必须真的引用过 |
| 附录 | 含完整源代码 | 9 页 | 逐问代码 + 中间数据 + 补充图表 |

写不够时，先问自己：公式推导是不是跳步了？算法复杂度分析写了吗？敏感性分析是不是只写了一句结论？备选模型的对比有没有写？每章末尾的「本章小结」加了吗？这些地方补起来，篇幅自然够，而且都是有效内容——**不要靠灌水凑页数**。

## 目录

67/100 的获奖论文带目录。front matter 默认 `toc: true`，builder 会插入 Word 目录域，导出 PDF 时自动填页码。**正文超过 40 页就必须带目录**；不要手写目录，页码会随排版变化失准。

## 摘要（最该花时间的一页）

评阅时摘要和论文都会审阅，摘要是第一印象。必须包含六个要素，缺一不可：

1. **建模思路**：一句话说清整体技术路线（如「先聚类分层，再对每层分别建模预测」）。
2. **主要方法**：具体到模型全名（写「BP 神经网络」而不是「神经网络」；写「熵权法-TOPSIS」而不是「综合评价」）。
3. **模型**：每个小问用了什么模型，逐问对应。
4. **结果与结论**：给出**具体数值**（最优解、误差、排序结果），不是「效果较好」。
5. **创新点**：与传统方法相比的差异，可量化（如「预测误差降低 20%」）。
6. **关键词**：3–5 个，含核心模型名与研究主题词。

写法：按「背景→问题→方法→结果→结论」推进，逐问段落以「针对问题 X」开头。**无公式编号、无图表、无引用。**

篇幅：**两页是硬上限**（`check_format.py --pdf` 会判定），800–1000 字是推荐区间（按 Word「字数」统计口径）。两者冲突时以两页为准。

## 1 问题重述

用**原创语言**梳理，不得整段复制原题。写三件事：问题背景（结合行业现状或痛点）、核心目标（优化/预测/评价/决策）、约束条件（数据范围、时间限制、资源上限）。可简要提及 1–2 篇相关文献的视角来深化理解。

## 2 问题分析

采用「总—分」结构：先给整体思路（一句话技术路线），再逐小问分析。每个小问写：①关键矛盾点；②解题思路框架；③核心步骤拆解与逻辑衔接。**只讲思路，不给结果**，每小问控制在一页内。可在结尾放一张解题流程图。

## 3 模型假设

列 3–5 条**与建模求解直接相关**的假设。每条必须含三部分：

- 假设内容（如「忽略极端异常值的影响」）。
- **合理性依据**（如「按 3σ 原则，异常值占比低于 0.5%，对趋势影响可忽略」）。
- 对模型的影响（如「简化计算复杂度，提升求解效率」）。

直接抄 `model-contract.md` 的假设条目——那里的每一条都已带依据。

## 4 符号说明

**三线表**，三列：符号 | 含义 | 单位。只列模型建立与求解中出现的**全局符号**，局部变量在正文首次出现处说明即可。符号必须与 `model-contract.md` 完全一致，正文不得出现表外符号。

## 数据预处理（需要时独立成节）

当附件数据需要清洗时（缺失、异常、量纲不一、需要构造特征），独立成一节，写清四件事：缺失值处理方法与依据、异常值检测方法与结果、标准化/归一化的选择理由、特征构造过程。素材取自 `solving/results-report.md` 与 `solving/data/processed/`。数据本来就干净时跳过这节，不要为凑结构硬写。

## 5 模型建立与求解

论文主体，**逐问展开**，每问固定五段式（获奖论文的通用链）：

- **问题分析**：该问的关键矛盾点、解题思路框架、核心步骤。只讲思路不给结果。
- **模型建立**：模型原理（如「灰色预测基于累加生成弱化随机性」）、变量定义、核心公式及**推导逻辑**，每步标注物理意义。公式用 `$$` 写成真公式，编号如 `(5-3)`。
- **算法设计**（有算法时）：算法流程、伪代码、**复杂度**（时间 O(·)、空间 O(·)）。优化类论文几乎必备。
- **模型求解**：求解工具（MATLAB / Python 的哪个库）、步骤（初始化→迭代→收敛判断）、关键结果（具体数值），并用**文字描述图表核心信息**（如「图5-1 显示预测值与实际值拟合 R²=0.9977」）。
- **结果分析**：①基础分析（结果符合什么趋势、在什么区间波动）；②深层分析（敏感性：哪个因素影响最大）；③直接回应问题（明确回答题目要求）。

数值一律取自 `solving/results-report.md`，禁止凭印象写数。

**本章小结**（可选但加分）：每问章末尾用 3–5 句回收结论。顶级论文普遍这么做。

## 6 模型检验

写清三件事：检验方法（残差检验/显著性检验/交叉验证/仿真检验/后验差检验）、检验步骤（计算残差→检验正态性→算后验差比）、检验结果（如「后验差比 C=0.28<0.35，小误差概率 P=0.96>0.95，精度一级」）。再补灵敏度与鲁棒性结论。

**检验要与求解平级**：写成 `5.5 模型检验` 这样的小节，而不是在结果里一笔带过。

## 7 模型的评价与推广

- **优点 3–5 条**：从创新性、适用性、效率三个维度写，每条**用数据支撑**（如「计算效率提升 40%，10 万条数据耗时由 5 分钟降至 3 分钟」）。
- **缺点 2–3 条**：假设限制、数据依赖、可扩展性局限，**具体到数值**（如「小样本下 K 不可辨识，变异系数达 2.047」），避免「模型有局限」这类空泛表述。
- **算法复杂度分析**（加分项）：给出时间与空间复杂度的量级。
- **精度评价与参数评价**（加分项）：如用蒙特卡洛评估参数敏感性。
- **推广**：说明模型可迁移到什么同类问题、需要调整什么。

## 参考文献

按正文**引用顺序**编号，格式见 `format-spec.md`。正文引用写成 `^[1]`（渲染为上标）。程序引用要注明来源。只列正文真正引用过的文献。

## 附录

放四类材料：①完整程序代码（标注语言与版本，关键步骤加注释）；②中间计算结果（矩阵运算、迭代中间值）；③处理后的数据（标准化数据表、清洗后样本）；④未进正文的补充图表。

程序代码从 `solving/code/` 原样复制，用围栏代码块包起来。附录不编号章节，按 `附录 A`、`附录 B` 或直接顺序列出。
