# 项目内参考库

写代码前先在这里找同类实现，**能改写就不从零造**。三个库分工不同：

- `resource/` —— 基础模型的 Matlab + Python 实现；模型选型目录在 `.opencode/skills/math-modeler/references/model-catalog.md`。契约里指定的模型在这里取模板。
- 两个目录都在项目根下，定位规则（含 `MATHSKILL_ROOT` 与 `--root`）见 `math-modeler/SKILL.md` 的「项目资产位置」。核对存在性：`python .opencode/skills/math-modeler/scripts/scan_resources.py --examples`。
- `code/` —— 45 个**组合模型**案例，每个 `.docx` 含完整题目 + 可运行源码。契约给出「组合模型」时从这里取结构。
- `write/` —— 2025 华为杯 A–F 真题的完整解题包，用来对齐**产出形态**（代码怎么组织、结果怎么呈现、图表怎么命名）。

## 二、`write/` 2025 华为杯真题范式库

根目录：`write/2025 <X>题思路+参考文献+代码+成品论文/`，每题为一位或数位老师（C老师、Z老师、L老师、W老师、G老师、H老师、X老师、Y老师）的完整解题包。

一个高质量解题包的典型结构（以 `2025 B题.../Z老师/` 为例）：

```
第一部分：B题/
  B题思路分析Z老师.pdf
  B题初步模型建立Z老师.pdf
  B题算法推荐Z老师.pdf
第二部分：B题问题1-3模型求解文档/
  问题一数学模型建立与求解-Z老师.pdf
  问题二数学模型建立与求解(用于写代码)-Z老师.pdf      ← 与 model-contract.md 同角色
  问题三数学模型建立与求解(用于写代码)-Z老师.pdf
第二部分：B题问题1-3代码与结果可视化/code/
  问题一代码.py  问题二代码.py  问题三代码.py           ← 逐问一个脚本
  PCA特征空间分布.png  特征重要性排序.png  ...           ← 全中文命名，一图一结论
  Problem2_Results.xlsx  Valid_Results.xlsx             ← 结果落盘
```

`2025 C题.../L老师/C题 问题代码包-L老师/` 给出另一种命名范式：`main_q1.m`~`main_q4.m` + `结果呈现/问题1-结果图像-图1-1.png`、`问题2-表1-正弦参数.csv`——**文件名直接对应论文图/表编号**，本 skill 的命名约定即取自此。

### 从 `write/` 学什么

- **代码组织**：逐问一脚本，脚本内「配置 → 读数据 → 建模 → 求解 → 落盘 → 出图」。
- **产出形态**：图表中文命名并编号；结果同时落 xlsx/csv；一图对应一个可写进论文的结论。
- **绘图风格**：`matplotlib.use("Agg")`、中文宋体 + Times New Roman、大字号（20+）、`axes.unicode_minus=False`、多图分类（概率图/结果图像/可视化）。
- **交接口径**：「用于写代码」的建模文档与 `model-contract.md` 是同一角色——写作手用论文，编程手用它。

⚠️ `write/` 中多数内容为 PDF 大文件，**不要整篇读取**。需要时只取 `代码与结果可视化` 下的 `.py`/`.m`/`.csv` 与文件名清单；PDF 仅在需要确认产出形态时按需查看。
