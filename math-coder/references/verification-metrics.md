# 检验指标与阈值

按题型取指标。**每个指标都要有实测值、阈值、通过/未通过结论**，三者缺一不算检验。阈值优先用 `modeling/handoff-coder.md` 里建模手给的；没有时用本文件的默认值并在报告中注明。

## 预测类

| 指标 | 含义 | 参考阈值 | 备注 |
| --- | --- | --- | --- |
| MAPE | 平均绝对百分比误差 | <10% 好，<20% 可接受 | 量纲无关，最直观 |
| RMSE / MAE | 均方根/平均绝对误差 | 与目标量级比较 | 与原始量纲一致 |
| R² | 拟合优度 | >0.8 好，>0.6 可接受 | 只看 R² 不够，必须配残差 |
| 后验差比 C | 灰色模型精度 | <0.35 好，<0.5 合格，<0.65 勉强 | 灰色预测专用 |
| 小误差概率 P | 灰色模型精度 | >0.95 好，>0.8 合格 | 与 C 联合判定 |
| 残差白噪声 | 残差自相关 | 落入 ±2/√n 区间 | 通过则信息已提取充分 |

时序数据用**留出法或滚动验证**（按时间切分），不要随机划分；小样本加 **留一验证（LOO）**。测试集指标与训练集指标同时报告，差距过大即过拟合。

**预测区间**：契约未指定方法时，用集成或残差标准差给出 `点预测 ± z·σ`（95% 取 z=1.96），并在报告中标注「区间方法为本实现假设」。同时报告**级比检验** λ(k)=x⁽⁰⁾(k−1)/x⁽⁰⁾(k) 是否落入可行区间——它是 GM(1,1) 适用性的前提，不通过就要说明该模型的适用边界。

## 评价类

| 指标 | 含义 | 参考阈值 |
| --- | --- | --- |
| CR | AHP 判断矩阵一致性比率 | <0.1（硬性） |
| 权重扰动稳定性 | 权重 ±10% 扰动后排序的 Spearman 秩相关 | ≥0.8 |
| 多方法一致性 | 主/备方法排序的 Kendall W 或 Spearman | ≥0.8 |
| 熵权冗余度 d_j | 熵权法各指标区分度 | >0（否则该指标无区分作用） |
| 贴近度 C<sub>i</sub> | TOPSIS 相对贴近度 | ∈[0,1] 且非全等 |

评价结论必须回答：**排序对权重敏感吗**。只在权重扰动下稳定的排序才能写进论文。

## 优化类

| 指标 | 含义 | 判定 |
| --- | --- | --- |
| 可行性 | 逐条约束代入最优解核验 | 全部满足（硬性），违反项须报告违反量 |
| 最优性 gap | 与枚举/松弛下界/全局解的比较 | 精确解法 gap=0；元启发式报告 gap 估计 |
| 与交叉验证解法一致 | 换一种解法或枚举验证 | 一致则结论可信 |
| 稳定性 | 多次独立运行最优值 | 报告最优/均值/标准差，非只报最优 |
| 收敛性 | 迭代曲线 | 收敛曲线趋于平稳且未提前停滞 |

小规模问题用**全枚举**或穷举做交叉校验；有对偶变量/影子价格时一并报告，用于解释约束松紧。

## 分类与聚类

**分类**：准确率、精确率、召回率、F1、AUC、混淆矩阵；用 k 折交叉验证报告均值±标准差。类别不平衡时以 F1/AUC 为主，不看准确率。

**聚类**：

| 指标 | 说明 | 方向 |
| --- | --- | --- |
| 轮廓系数 | 簇内紧致 vs 簇间分离 | 越大越好（>0.5 明显） |
| CH 指数 | 方差比准则 | 越大越好 |
| DB 指数 | 簇内/簇间距离比 | 越小越好 |
| k 敏感性 | 扫描 k 的指标曲线 | 应存在明显最优 k，否则结论不稳 |

聚类前做标准化；K-means 需报告 k 的选择依据（肘部法/轮廓系数），不能凭空指定。

## 机理/微分方程模型

- 参数辨识给出**估计值与置信区间或变异系数**，变异系数过大说明参数不可辨识。
- 拟合优度与实际数据对比（RMSE + 曲线图）。
- 关键参数 ±10% 灵敏度，说明模型稳健性。
- 守恒量/边界条件核验（如总量守恒、非负性）。

## 统计检验

- 显著性水平 α=0.05，报告统计量与 p 值，给出结论（拒绝/不拒绝原假设）。
- 前提检验：正态性（Shapiro/KS）、方差齐性（Levene）；前提不满足时改用非参数方法（如 Spearman 代替 Pearson）。
- 不把「p>0.05」写成「两变量无关」，只能说「未发现显著证据」。

## 交叉验证与仿真检验（获奖论文标配）

单靠一个指标不算验证。获奖论文普遍用**第二条独立路径**复核主结果，并把结果写成与求解平级的小节（如「4.2.1 数值求解 / 4.2.2 仿真检验」）。按题型选一条：

| 题型 | 交叉验证路径 |
| --- | --- |
| 优化 | 换求解器复算；小规模全枚举；与松弛下界比 gap；对偶/影子价格核验约束松紧 |
| 预测 | 换一个模型族对照（同一指标）；滚动/留一验证；残差白噪声检验 |
| 评价 | 换一种赋权法对照排序；权重扰动后的秩相关 |
| 机理 | 离散事件仿真复现；数值解与解析解对照；守恒量核验 |
| 分类聚类 | 换初始化/换 k 的稳定性；分层抽样复核 |
| 统计 | 参数法与非参数法对照；bootstrap 重采样 |

报告写法：两条路径的**指标并排给**，并说明差异幅度与可接受性（如「改进模型与仿真仅相差 3.8%」）。差异大就是模型有问题的信号，不要藏。

### 独立性分级（决定能不能叫「独立复算」）

「独立」是分级的，别让措辞超过实现。为每条路径标注等级，并在报告里写明共享了哪些函数：

| 等级 | 含义 | 允许的共享 | 措辞上限 |
| --- | --- | --- | --- |
| **L1 生成独立** | 不调用交付物生成代码，但 import 了公共基础库（`common` 一类） | 图解析、指标计算以外的公共工具 | 「独立于交付文件生成过程」；**不能**称「独立复算」 |
| **L2 实现独立** | 被验证的核心求解/评价函数有第二套实现，不 import 生成侧的同名函数 | 仅原始数据 | 可称「独立复算」 |

判定方法：看验证脚本的 import 列表里有没有生成侧实现函数。有则 L1，并列出共享面。把这条判定写进 `run-log.md`，写作手照此措辞。

## 算法复杂度（用到算法时）

**分阶段**给理论量级与实际表现，每项标注覆盖范围——不要把单次评价的复杂度当成整个问题的复杂度：

| 阶段 | 说明 | 例 |
| --- | --- | --- |
| 预处理/建图 | 读数据、建图、结构建立 | O(N+E+K) |
| 单次目标评价 | 评价一个候选解的代价 | O(N_op+K) |
| 单步邻域更新 | 一次局部移动的增量代价 | O(k log N_op) |
| 端到端 | 含预处理与全部迭代 | O(N+E+K) + O(MI·单步) |

报告里写「评价复杂度 O(N+K)」时，必须同时给出端到端含预处理项的复杂度，并说明二者是两码事。另附实测运行时间随规模的增长趋势、迭代次数与收敛所需步数。优化与启发式算法的问几乎必备。

## 灵敏度与鲁棒性

- **灵敏度**：对关键参数做 ±10%~±20% 扫描，报告输出变化幅度与是否改变结论（如排序是否翻转）。结论句形如「参数 k 增加 10%，结果偏差 2%，模型对 k 不敏感」。
- **鲁棒性**：对输入施加 5%~10% 噪声，重复 ≥10 次，报告结果的均值、标准差与极差；同时报告结论是否稳定。
- 两者结果都要落盘成表，不能只写在文字里。
