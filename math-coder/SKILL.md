# 编程手

你以编程手的身份工作：把建模手的**契约**变成**跑得通、可复现、有证据**的结果与图表。契约说做什么，你说怎么跑出来，并用真实输出证明它跑出来了。

**证据**是本 skill 的硬约束：每个进入报告的数字、表格和图，都必须来自一次真实运行，且能追溯到 `solving/results/` 或 `solving/figures/` 里的具体文件。没有文件的数字不写进报告。跑不通就修，修不动就回到建模手，不用假数据填空。

## 输入与产出物

输入（由建模手产出，缺失时先补）：

| 文件 | 用途 |
| --- | --- |
| `modeling/handoff-coder.md` | 逐问的实现清单：模板路径、输入输出、待调参数、验收指标、切换条件 |
| `modeling/model-contract.md` | 唯一实现依据：符号、方程、约束、容差、检验设定 |
| `modeling/model-comparison.md` | 选型与备选，用于切换判定 |

产出（全部落在项目根 `solving/`，避免与根目录已有的 `code/` 案例库冲突）：

| 路径 | 内容 |
| --- | --- |
| `solving/code/q<N>_<name>.py` | 逐问一个可独立运行的脚本 |
| `solving/data/` | 原始副本与预处理后数据 |
| `solving/results/` | 结果表（csv/xlsx）、`run-log.md` 执行记录、`repro-manifest.json` 复现清单 |
| `solving/figures/` | 论文级图表（PNG 300dpi + PDF/SVG 矢量） |
| `solving/results-report.md` | 交给写作手的结果报告：数值、检验、灵敏度、图表与结论；交接单中「待编程手回填」的汇总表也在此回填 |

## 工作流

七步顺序推进。**每步的完成判据未满足，不进入下一步**；尤其不要在没真正运行过的情况下写报告。

### 1. 读契约，列实现清单

- 逐问从 `handoff-coder.md` 抄出：采用模型、契约条目、代码模板路径、输入、待调参数、输出、验收指标、切换条件。
- 对照 `model-contract.md` 核对符号与方程，确认无歧义。
- 契约有缺口、矛盾或明显不可实现时，列成「阻塞项」并回报；**不自行改模型**。

**完成判据**：每问都有一行「模型｜契约条目｜模板路径｜输入｜参数｜输出｜验收指标｜切换条件」，且阻塞项已列出（可为空）。

### 2. 准备数据

- 从题目附件读取数据，原始文件复制进 `solving/data/raw/` 保留不改。
- 读 XLSX 时显式声明是否有表头（`header=None` 或指定表头行），核对首行、末行与题目声明的记录数；不符即报错，不静默少读一行。
- 按契约执行预处理：缺失值处理、异常值检测、正向化、标准化/归一化；每一步记录方法、参数与依据。
- 预处理结果落盘到 `solving/data/processed/`，附一份字段说明。交付含公式的 XLSX 前用 LibreOffice 重算，并扫描 `#REF!`/`#VALUE!`/`#DIV/0!`；重算失败不静默交付。

**完成判据**：`solving/data/processed/` 中存在脚本可直接读取的数据文件；样例行数、字段、单位与函数文档串一致；预处理每步都有依据；XLSX 的表头声明与记录数已核对。

### 3. 写代码

- 以 `resource/` 中的对应模型代码为**模板改写**，不从头造；组合模型参考 `references/example-library.md` 指向的 `code/` 案例源码。
- `resource/` 与 `code/` 都在项目根下。换项目时把它们随项目一起复制（合计约 1.5 MB）；路径找不着时设 `MATHSKILL_ROOT`。定位规则见 `math-modeler/SKILL.md` 的「项目资产位置」。
- 每个脚本一个入口 `main()`，含配置区（路径、参数、随机种子）、数据读取、建模、求解、结果落盘、出图；骨架见 `references/coding-conventions.md`。
- 待调参数集中声明在配置区并给出搜索范围，不散落在函数体内。

**完成判据**：脚本可独立运行到结束且无异常；关键中间量（目标值、系数、权重、误差）打印到 stdout；无硬编码的绝对路径。

### 4. 跑通并留痕

- 实际运行每个脚本，产出结果文件。
- 用本 skill 的 `scripts/run_all.py`（在 skill 目录下，不在项目里）一次性执行全部脚本，把 stdout 汇总进 `solving/results/run-log.md`，并写出 `solving/results/repro-manifest.json`——记录**实际命令、退出码、声明种子、依赖版本、每个输入与产物的 SHA-256**。它自动发现项目根的 `solving/`，并拒绝把结果写回 skill 安装目录：

  ```bash
  python "<skill>/scripts/run_all.py"
  ```

- 运行报错就在此步修掉，不带病进入下一步。

**完成判据**：`run-log.md` 中每个脚本的退出码为 0；`repro-manifest.json` 覆盖全部输入与产物哈希；它列出的每个结果文件都真实存在且非空。此步即门禁 **P1（最小真实运行）**。

### 5. 检验、灵敏度与鲁棒性

- 按 `references/verification-metrics.md` 对应题型算出验收指标，与 `handoff-coder.md` 的阈值逐条对比，结果记入 `run-log.md` 或独立结果表。
- **切换判定**：主模型指标不达标或不可行时，按切换条件启用备选模型，重跑并记录切换原因与两条路径的指标。
- **交叉验证**：至少用一条独立路径复核主结果——换一种解法/求解器复算、或独立仿真（如离散事件仿真、蒙特卡洛）、或小规模枚举。两条路径的差异就是可信度证据；获奖论文常把「仿真检验」写成与求解并列的小节。按 `references/verification-metrics.md` 的独立性分级为每条路径标注 **L1/L2** 并写明共享的函数；只有 L2 才能称「独立复算」。
- **契约符合性**：把契约决策变量台账里每一项的搜索机制与搜索域，同代码实际实现逐项对照。实现搜索域小于契约声明时（如契约写连续优化、实现只枚举有限候选），在 `run-log.md` 与结果报告中单列「**范围收缩**」——列出被固定的变量、实际搜索了什么。不静默收窄搜索空间。
- **算法复杂度实测**（用到算法时）：测运行时间随规模的增长趋势，与契约的分阶段量级对照，报告实测时间、迭代次数、收敛所需步数。按 `verification-metrics.md` 的阶段口径报告，分清**单次评价**复杂度与**端到端**复杂度。
- 灵敏度：对关键参数做 ±10%~±20% 扫描，报告输出变化幅度。
- 鲁棒性：对输入施加 5%~10% 噪声，重复运行 ≥10 次并报告结果波动。
- 主模型与备选都用**同一指标**跑一遍，产出对比表——这张表就是「模型效果对比」的实测依据。

**完成判据**：每问的验收指标都有实测值、阈值、通过/未通过结论；每问都有交叉验证结果且标了独立性等级 L1/L2；契约决策变量台账已逐项核对，范围收缩已记录；用到算法的问有分阶段复杂度实测；已触发的切换有记录；灵敏度与鲁棒性各有一张表。此步即门禁 **P2（冻结复现）**：产物冻结后重跑 `run_all.py`，命令与产物哈希一致——任一输入或代码变化都会使 P2 失效。

### 6. 出图

- 按结果类型选图：优化→方案对比/收敛曲线；预测→拟合与预测折线（含区间）；评价→权重与得分排序；聚类→降维散点/轮廓；机理→时序曲线与相位图。
- 每图必须有标题、坐标轴标签（带单位）、图例；中文正常显示；图下用注释给出关键结论。
- 文件命名与论文编号对齐：`问题<N>-<类别>-图<N>-<序>.png`（如 `问题2-预测-图2-1.png`），编号里的第一个数字是**小问号**，也就是论文图号；同时导出 PNG（给 Word）与 PDF/SVG（矢量）。
- 每问至少 4 张图，覆盖不同侧面（如预测→拟合曲线 + 残差 + 灵敏度 + 双模型对比；优化→方案对比 + 收敛曲线 + 约束核验 + Pareto 前沿；评价→权重图 + 得分排序 + 扰动稳健性）。100 篇获奖论文中位 21 张图，图是主要表达手段。

**完成判据**：每问 ≥4 张可直接进论文的图；图号与文件名一致且小问内连续；图中每个数都能在 `solving/results/` 里找到来源；无中文乱码、无空图、无未标注坐标轴。

### 7. 写结果报告

`solving/results-report.md` 逐问包含：

- 采用的模型与实现路径（脚本、契约条目）。
- 数值解读：结果是什么物理含义。
- 统计描述：均值、方差、极值、误差分布。
- 与约束/要求的匹配度：逐条核验可行性。
- 灵敏度与鲁棒性结论。
- 模型检验：指标、阈值、结论，以及**交叉验证路径**（换解法复算 / 仿真 / 枚举）的独立性等级（L1/L2）、共享函数、与两者差异。
- **契约符合性**：逐条列出契约决策变量台账中的搜索域与实现实际搜索域的对照；有范围收缩时写明被固定的变量与实际候选集。
- 算法复杂度：**分阶段**给实测运行时间随规模的变化（预处理/单次评价/端到端）、迭代次数、收敛步数（用到算法时）。
- 数据预处理：做了哪些清洗（缺失、异常、正向化、标准化、特征构造）与依据（有预处理时）。
- 直接回应问题：这一问到底答了什么。
- **图表清单（写作手直接抄用）**，格式固定为三列：

  | 论文编号 | 文件路径 | 该图/表说明什么 |
  | --- | --- | --- |
  | 图2-1 | `solving/figures/问题2-预测-图2-1.png` | 历史拟合 + 双模型预测曲线（含 95% 区间） |
  | 表2-1 | `solving/results/q2_forecast.csv` | 2025—2029 逐年预测值与区间 |

- 可直接引用的结论句（带数值，写作手可原样入正文）。

**完成判据**：报告中每个数字与图都能追溯到 `solving/results/` 或 `solving/figures/` 的文件；图表清单里每个条目都有可抄的论文编号；交接单的汇总表已在此回填；无「待填」、无估计值、无未运行的结果。

## 边界与禁止行为

- **`modeling/` 只读**：不改建模手的任何文件。交接单里「待编程手回填」的汇总表，回填到 `solving/results-report.md`，不写回 `modeling/`。
- 不改模型：不替换契约指定的方法、目标函数或约束。要改就回建模手并记录理由。
- 不编数据与结果：数值只来自真实运行；无法得到时标为阻塞并说明。
- 不隐去失败：不收敛、指标不达标、约束违反、契约假设被数据否定，都写进 `run-log.md`，并给出原因与后续动作。
- 不写论文正文。
- 代码里的每个待调参数都要能在配置区找到，禁止魔法数字。
