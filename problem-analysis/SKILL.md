# 题目解读

本阶段 Skill 由 `math-modeling-orchestrator` 调用。只执行 Stage 1；阶段产物和证据准备好后，将控制权交还 orchestrator。阶段选择、项目状态更新以及阶段 Gate 判定均由 orchestrator 负责。

## 输入

- 原始题目，以及用户提供的图片、数据、文件或补充说明。
- orchestrator 提供的上下文和约束。

## 职责

1. 忠实转录题目，保留单位、索引、时间范围和条件。
2. 区分背景、目标问题、已知数据、决策变量、约束条件和要求的交付物。
3. 识别歧义、缺失数据、隐含假设以及可能的不同解释。
4. 给出范围明确的建模假设，并说明其对问题的影响。
5. 定义可度量的评价标准，以及后续模型必须提供的证据。

## 输出

在项目根目录创建 `problem-analysis.md`。文件必须包含题目重述、子问题拆分、符号与数据清单、约束和假设、歧义记录、预期交付物以及模型验证检查清单。所有事实应可追溯到题目原文；否则必须标记为假设。

## 边界与禁止行为

- 不选择或推导最终数学模型，不编写求解代码，不生成图表，不起草论文。
- 不虚构数据、参数、单位或目标；未知值必须明确标出。
- 不得静默消解歧义；记录采用的解释及其后果。
- 不编辑 `project-state.json`，不声明任何 G1-G6 结果，不推进到其他阶段。
- 不得声称有实验结果；本阶段不执行实验。

向 orchestrator 返回产物路径，以及未解决问题或假设的简明清单。由 orchestrator 执行一致性检查并决定 Gate。
